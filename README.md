# AI키우기 웹사이트 리뉴얼 — 문서 안내

디자인리서치(1) HCI 학회용 웹사이트 리뉴얼 프로젝트의 기준 문서 모음입니다.
사람과 AI 모두 작업 전에 이 문서들을 기준으로 삼습니다.

| 파일 | 내용 | 언제 보나 |
|---|---|---|
| `CLAUDE.md` | AI 코딩 도구용 작업 규칙 (Cursor라면 `.cursorrules`로 복사) | 모든 작업 시작 시 |
| `docs/PRD.md` | 목적, 대상 사용자, 핵심 행동, 성공 기준 | 방향 판단이 필요할 때 |
| `docs/IA.md` | 사이트맵, 사용자 플로우, 내비게이션, URL | 페이지/링크 작업 시 |
| `docs/PAGES.md` | 페이지별 섹션 구성, 콘텐츠, CTA | 페이지 구현 시 |
| `docs/FEATURES.md` | 기능 명세, 인터랙션, 상태(로딩/빈/에러), 예외처리 범위 | 기능 구현 시 |
| `docs/DESIGN.md` | 디자인 토큰, 컴포넌트 정의, 이미지 규칙 | 스타일/컴포넌트 작업 시 |
| `docs/CONTENT.md` | 콘텐츠 인벤토리, 촬영 리스트(샷 리스트), 이미지 매핑 | 콘텐츠/사진 준비 시 |
| `docs/TECH.md` | 기술 스택, 폴더 구조, 네이밍 규칙, 발표 전 체크 | 개발 환경 세팅 시 |

## 표기 규칙
- `TODO(팀)` : 팀이 채우거나 결정해야 하는 항목
- `제안` : 초안 단계의 제안값. 팀이 확정하면 `제안` 표기를 지웁니다.
- 결정이 바뀌면 해당 문서를 먼저 고친 뒤 AI에게 작업을 요청합니다. (문서가 항상 코드보다 앞선다)

## 결정이 필요한 항목 (Open Questions)
대부분 정해졌고, 아래만 팀 확인이 남았습니다.

1. **디자인 방향**: 발표자료와 같은 다크 + 민트로 통일할지 → `DESIGN.md` §0
2. **메인 사진 ②의 연결**: 키트 설명으로 연결했는데, 별도 '사이트 소개'를 의도했는지 → `IA.md` §6
3. **키트 구성 관계**: 초대장은 도시락통 안에, 캡슐 안에는 무엇이 들어가는지 → `CONTENT.md` §3
4. **가입 시 연락처 수집**: 테스트 참여자 개인정보이므로 선택 입력/제외 권장 → `PAGES.md` §5
5. **선언문 인용 출처**: 톨스토이 구절의 원 작품 확인 → `CONTENT.md` §2
6. **커뮤니티 예시 글**: 논문에 실릴 수 있으므로 팀이 직접 다듬기 → `CONTENT.md` §4
