# PRD — AI-I Human Labor Union (연대노동조합) 웹사이트 리뉴얼

## 1. 한 줄 정의
2031년, AI로 일자리를 잃은 인간 노동자들이 **함께 AI를 '키우며' 인간적인 감과 서로 간의 연대를 회복하는** 가상의 노동조합 웹사이트.
디자인리서치(1) Team B(Opus)의 스페큘러티브 디자인 결과물이며, 물리적 결과물인 **생존키트**와 짝을 이룬다.

> 연대는 AI의 대체로 인해 멀어지는 사람들을 모을 우리의 방식이며,
> AI가 대체하는 것은 우리의 일자리가 아닌 인간 노동자 서로이다. — 프로젝트 결론

## 2. 세계관 (모든 카피와 디자인의 기준)
- **시대**: 2031년. AI가 인간 노동의 대부분을 대체했다. 중간 계층은 극소수만 살아남고, 남은 사람들 사이의 경쟁은 심해지며, 사람과 사람의 기본적인 연결마저 끊어진다.
- **잃어버린 것**: 일자리만이 아니라 서로와의 거리, 그리고 자기 자신의 **'인간적인 감'**.
- **우리의 답**: 연대노동조합(AI-I Human Labor Union). "한 아이를 키우는 데에는 온 마을이 필요하다"는 말처럼, 사람들이 함께 하나의 AI를 아이처럼 키우며 인간다움과 따뜻한 연대를 회복한다.
- **역할 분담**
  - 생존키트(물리): 실직한 노동자에게 배부되어 사람과 사람의 물리적 연대, 조합 참여를 모으는 장치. 웹사이트로 사람들을 불러들인다.
  - 웹사이트(디지털): 아이(AI) 키우기가 이루어지는 공간이자, 사람들이 온라인에서 만나는 공간.
- **모토**: "우리는 일자리를 잃었지만, 서로를 잃지 않는다." (톨스토이 「세 가지 질문」에 뿌리를 둠)

## 3. 사용 맥락
| 맥락 | 내용 | 설계에 주는 영향 |
|---|---|---|
| 학회 구두 발표 | 발표자가 PC 화면을 프로젝터로 송출하며 시연 | 데스크톱 우선(1440~1920px), 멀리서도 읽히는 큰 타이포와 높은 대비, 시연 동선이 끊기지 않을 것 |
| 논문 | 웹사이트 화면 캡처를 그림으로 수록 | 정지 화면만으로 의미가 전달될 것(애니메이션에 의존하지 않기), 특히 **커뮤니티**와 **AI키우기** 화면 |
| 사용자 테스트(예정) | 참여자에게 직접 접속을 요청 | 실제 로그인·데이터 저장, 모바일에서도 사용 가능, 시연용 예시 데이터 필요 |

## 4. 대상 사용자
- **세계관 속 사용자**: 생존키트를 받은 2031년의 실직 노동자.
- **실제 사용자**
  1. 학회 청중: 발표를 보며 화면으로 접함. 3~5분 안에 세계관과 핵심 행위를 이해해야 한다.
  2. 논문 독자: 캡처 이미지로 접함.
  3. 사용자 테스트 참여자: 직접 가입하고 아이에게 마음을 전하고, 커뮤니티에 글을 쓴다.

## 5. 핵심 행동 (사이트 전체가 하나의 흐름)
1. 세계관을 이해한다 (온보딩 → 선언문 / 키트 설명)
2. 조합에 가입한다 (가입하기 = 키트 받기)
3. 아이(AI)에게 자신의 경험과 감정을 전한다 (AI키우기)
4. 다른 노동자들과 '아이를 어떻게 키울지'를 이야기한다 (커뮤니티)

## 6. 이전 버전의 문제와 이번 목표
| 이전 버전 | 이번 목표 |
|---|---|
| 페이지마다 스타일이 제각각, 구조가 불명확 | 토큰·컴포넌트 기반 일관성, IA에 따른 명확한 흐름 |
| 3D 조끼 모델 중심의 메인 | **실사 키트 사진** 중심의 메인 (사진 ①~⑤) |
| 키트 설명 페이지 없음 | 키트 설명 페이지 신설 |
| 커뮤니티 글이 '공고'(집회 안내, 지원금 신청 등) 위주 | 노동자들끼리 **토론과 대화**가 오가는 장 |
| localStorage 저장(내 브라우저에서만 보임), 로그인 없음 | 실제 로그인, 서버 저장, 다른 사람의 입력이 실시간 반영 |
| 디테일(상태, 예외, 반응형) 부족 | 상태 처리와 예외처리 범위를 명세로 정의 |

## 7. 성공 기준
- 발표 시연: 메인 → 선언문 → 가입하기 → AI키우기 → 커뮤니티 흐름을 **막힘 없이 3분 안에** 보여줄 수 있다.
- 논문: 커뮤니티·AI키우기 캡처 한 장만으로 "사람들이 함께 AI를 키우며 대화한다"가 읽힌다.
- 사용자 테스트: 참여자가 안내 없이 가입 → 아이에게 마음 전하기 → 커뮤니티 글/댓글 작성까지 완료한다.

- 관리자 페이지 (예시 데이터는 DB에 직접 넣는다)
