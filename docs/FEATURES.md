# FEATURES — 기능 명세

## 0. 구현 수준
| 구분 | 결정 |
|---|---|
| 로그인 | **실제 동작** (사용자 테스트 대비) |
| 데이터 저장 | **실제 서버 저장** (Supabase, `TECH.md`) — 다른 사람의 입력이 모두에게 보인다 |
| 가입 절차 | 세계관상 가상 절차(키트 발송은 연출), 계정 생성은 실제 |
| 시연 데이터 | 처음부터 예시 데이터가 들어 있다 (§4) |
| 예외처리 | §6에 정의된 범위까지만 |

## 1. 인증
- 방식: 이메일 + 비밀번호 (Supabase Auth). 이메일 인증 메일은 **끔** (테스트 진행 편의).
- 비로그인 사용자도 모든 페이지를 **볼 수 있다**. 로그인이 필요한 행동:
  - AI키우기에서 마음 전하기
  - 커뮤니티 글쓰기, 댓글, 공감
- 로그인이 필요한 행동을 시도하면 → 안내 모달 "조합원만 할 수 있어요" + [가입하기] [로그인]. 완료 후 원래 자리로 복귀.
- 로그인 상태 표시: GNB 우측에 "No.#3903 ○○○" + 로그아웃.
- 조합원 번호: 가입 순서대로 부여, 세계관 숫자에 이어서 시작 (예: 3903부터).
- **발표용 계정**: `demo@…` 계정을 미리 만들어 두고 발표 때 사용. (`TODO(팀)` 계정 정보는 저장소에 넣지 말고 팀 내부에서만 공유)

## 2. 온보딩
- 첫 방문 여부는 브라우저에 저장(`localStorage`의 `onboarded` 플래그).
- `/`에 처음 들어오면 `/intro`로 이동. 건너뛰기·완료 시 플래그 저장 후 `/`.
- GNB 로고를 길게 누르거나 `/intro`로 직접 가면 다시 볼 수 있다 (발표 리허설용).
- 키보드: `→`, `Space` 다음 장면 / `←` 이전 장면 / `Esc` 건너뛰기.

## 3. 인터랙션

### 3.1 아이(AI)의 형태와 반응 — AI키우기
- **기본 상태**: 화면 중앙의 반투명하고 유기적인 덩어리(blob). 천천히 숨 쉬듯 미세하게 울렁인다.
- **색**: 최근 마음들(예: 최근 50개)의 감정 색을 섞은 그라데이션. 감정 색은 `DESIGN.md` §1.3 감정 팔레트.
- **크기·선명도**: 전체 마음 수가 늘수록 아주 조금씩 커지고 또렷해진다 (희미함 → 존재감).
- **내가 전했을 때**
  1. 입력한 문장이 작은 빛 입자가 되어 아이에게 흘러 들어간다 (0.8s)
  2. 아이가 크게 한 번 울렁인다 — 진폭은 글 길이에 비례 (1.2s)
  3. 선택한 감정의 색이 아이 안쪽에서 퍼져 섞인다 (2s)
  4. "전해졌어요. 아이가 당신의 마음을 기억합니다."
- **다른 사람이 전했을 때(실시간)**: 같은 연출을 약하게(진폭 30%) + 피드에 새 항목.
- 마우스를 가까이 대면 아이가 살짝 반응(끌려오거나 밀려남) — 선택 사항, 성능 확보 후.
- 구현: WebGL 노이즈 셰이더 또는 Canvas 메타볼. 라이브러리는 `TECH.md` §1.

### 3.2 마음 피드 — AI키우기
- 최신 20개 표시, 새 항목은 위에서 부드럽게 등장.
- 항목: 감정 칩 · 내용 · 이름 · "3분 전".

### 3.3 버블 광장 — 커뮤니티
- 버블은 서로 겹치지 않게 천천히 떠다닌다 (물리 시뮬레이션 또는 미리 계산한 배치 + 미세한 흔들림).
- 크기: 댓글 수 + 공감 수에 따라 3단계 (S / M / L).
- 호버: 버블이 살짝 커지고 첫 문장이 보인다. 클릭: 상세 오버레이.
- 필터 변경: 해당되지 않는 버블은 흐려지고 작아진다(사라지지 않음 — 광장의 밀도 유지).
- 새 글 작성 → 화면 아래에서 새 버블이 떠오른다.

### 3.4 캡처 모드 (논문·발표 자료용)
- URL에 `?capture=1`을 붙이면: 모든 움직임 정지, 버블 위치 고정, 커서 힌트·토스트 숨김, 메인 로딩 화면 생략, 메인 스크롤 연출 대신 정지 배치(§3.6).
- 같은 데이터면 항상 같은 배치가 나오도록 버블 배치에 고정 시드 사용.

### 3.5 메인 로딩 화면 (2026-11-17 추가)
- **언제**: 메인(`/`)에 들어올 때마다 — 새로 접속, 새로고침, 다른 페이지에서 메인으로 이동 모두 포함.
  - 첫 방문은 먼저 `/intro`(§2)로 가고, 온보딩을 마치고 메인에 올 때 로딩 화면이 나온다.
- **모습**: `--color-header` 배경 위 가운데에 로고 심볼(`logo.svg`)이 아래에서 떠오르며 나타났다가, 화면 전체가 사라지며 히어로가 드러난다. 문구 없음.
- **시간**: 등장 `--dur-slow` → 유지 `--dur-slow` → 퇴장 `--dur-slow` (약 1.8초). 데이터 로딩을 기다리지 않는 연출용 화면이다.
- **건너뛰기**: 클릭, 아무 키(발표 리모컨 포함)로 즉시 사라진다. 발표 중 메인을 여러 번 오갈 때 흐름이 끊기지 않게.
- **생략**: 캡처 모드(§3.4). `prefers-reduced-motion`이면 움직임 없이 짧게 보였다 사라진다.
- `TODO(팀)` 메인에 올 때마다 보이는 것이 발표 시연(PRD §7, 3분 흐름)에 방해되는지 리허설에서 확인.

### 3.6 메인 스크롤 연출 (2026-11-17 추가)
- 대상: 메인 섹션 2~5 (`PAGES.md` §2). 섹션 1(히어로)은 일반 화면.
- **데스크톱(lg 이상)**: 섹션 2~5를 감싸는 구간이 화면에 고정(sticky)되고, 스크롤 진행에 따라
  1. 사진이 다음 장으로 교차 전환 (`--dur-slow`, `--ease-in-out`)
  2. 텍스트 패널이 바뀜 — 들어오는 쪽에서 살짝 밀려 들어오며 나타남
  3. 진행 점과 "0N — 05" 카운터가 갱신. 점을 누르면 해당 장으로 스크롤
- 한 장당 화면 높이 1개 분량을 스크롤한다. 휠·트랙패드·키보드·스크롤바 모두 일반 스크롤로 동작 (스크롤을 막거나 가로채지 않음).
- **모바일·태블릿(lg 미만)**: 고정하지 않고 섹션을 세로로 나열. 각 섹션이 화면에 들어올 때 가볍게 나타나는 정도만.
- **캡처 모드·`prefers-reduced-motion`**: 고정·전환 없이 섹션 2~5를 세로로 나열한 정지 배치. 모든 장의 사진과 글이 그대로 보인다.
- 구현: Motion(`TECH.md` §1)의 스크롤 진행값. 새 라이브러리 없음.

## 4. 데이터와 시연용 예시
- 예시 데이터는 `supabase/seed.sql`로 관리, 언제든 다시 넣을 수 있게 한다.
- 예시 데이터에는 `is_seed = true` 표시 (나중에 실제 테스트 데이터와 구분해서 분석하기 위해).
- 세계관 숫자(102,418개의 마음, 3,902명 서명 등)는 **기본값 + 실제 증가분**으로 표시. 기본값은 `src/content/world.ts`.
- 예시 콘텐츠 원문: `CONTENT.md` §4, §5.

## 5. 데이터 모델 (Supabase / Postgres)
```
profiles     id(=auth.users.id), display_name, prior_job, reasons text[], message,
             member_no int unique, phone (nullable), pledged_at, is_seed, created_at
feelings     id, user_id → profiles, emotion (enum 8종), body text(≤300), is_seed, created_at
posts        id, user_id → profiles, category (enum), title, body, is_pinned (오늘의 질문),
             is_seed, created_at
comments     id, post_id → posts, user_id → profiles, body, is_seed, created_at
reactions    post_id, user_id, created_at  (공감, 1인 1회, PK=post_id+user_id)
```
- 감정 enum: `longing 그리움 · hope 희망 · joy 기쁨 · loneliness 외로움 · calm 평온 · sadness 슬픔 · fear 두려움 · anger 분노`
- 커뮤니티 카테고리 enum: `discussion 키움 토론 · today 오늘의 마음 · kit 생존키트 · meetup 만남 제안`
- 보안(RLS): 읽기는 모두 허용, 쓰기는 본인 user_id로만, 수정·삭제는 본인 것만.
- 실시간: `feelings`, `posts`, `comments` insert를 Realtime으로 구독.

## 6. 상태와 예외처리 범위
아래까지만 처리한다. 이보다 더 필요하면 문서에 먼저 추가한다.

| 상황 | 처리 |
|---|---|
| 데이터 로딩 중 | 스켈레톤(형태만 있는 회색 블록). 아이는 희미한 기본 형태로 먼저 표시 |
| 데이터 0개 | 빈 상태 문구 — 피드: "아직 아무도 마음을 전하지 않았어요. 첫 번째가 되어주세요" / 커뮤니티: "광장이 조용해요. 첫 이야기를 띄워주세요" |
| 네트워크·서버 오류 | 토스트 "연결이 잠시 끊겼어요. 다시 시도해 주세요" + 입력 내용 유지 |
| 폼 검증 | 필수값 누락, 이메일 형식, 비밀번호 8자 이상, 글자 수 초과 — 입력칸 아래 빨간 안내, 제출 버튼 비활성 |
| 중복 이메일 가입 | "이미 조합원이에요. 로그인해 주세요" + 로그인 링크 |
| 로그인 실패 | "이메일 또는 비밀번호를 확인해 주세요" |
| 연속 제출 | 제출 중 버튼 비활성 + 로딩 표시, 같은 내용 2초 내 재제출 방지 |
| 이미지 로드 실패 | 회색 배경 + 대체 텍스트 |
| 없는 주소 | 404 페이지 |
| 부적절한 글 | 이번 범위에서는 필터 없음. 본인 글 삭제만 가능. 테스트 중 문제 글은 팀이 DB에서 직접 삭제 |

## 7. 반응형·접근성
- **기준 해상도**: 1920×1080(발표), 1440×900(논문 캡처). 이 두 화면에서 가장 완성도 높게.
- 모바일(390px)에서도 모든 기능 사용 가능 — 사용자 테스트 참여자가 폰으로 접속할 수 있음.
- 모든 이미지 `alt`, 버튼은 키보드로 조작 가능, 포커스 표시 유지.
- `prefers-reduced-motion`이면 울렁임·떠다님을 최소화.
